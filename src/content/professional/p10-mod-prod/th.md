## explanation
บรรทัด `go` ใน go.mod คือรุ่นภาษาขั้นต่ำที่โมดูลต้องการ ตั้งแต่ Go 1.21 เป็นต้นมา ถ้า Go ในเครื่องเก่ากว่ารุ่นนี้ จะไม่ build ด้วยรุ่นเก่า

```
module example.com/api

go 1.25

toolchain go1.25.3
```

- `go 1.25`: โค้ดใช้ความสามารถของภาษาถึงรุ่น 1.25 และต้อง build ด้วย Go 1.25 ขึ้นไป
- `toolchain go1.25.3`: ชุดเครื่องมือที่แนะนำ ถ้าเครื่องมีรุ่นเก่ากว่านี้ Go จะสลับไปใช้รุ่นนี้

toolchain คือตัวโปรแกรม `go` ทั้งชุด รวม compiler และเครื่องมืออื่น ส่วนบรรทัด go คือรุ่นของภาษา สองอย่างนี้จึงไม่เหมือนกัน

## apply
ตัวแปรสภาพแวดล้อม `GOTOOLCHAIN` ควบคุมว่า Go จะสลับรุ่นได้ไหม:

- `auto` (ค่าเริ่มต้น): ถ้า go.mod ขอรุ่นใหม่กว่าที่ติดตั้ง Go จะดาวน์โหลดรุ่นนั้นมาใช้เอง
- `local`: ใช้แค่รุ่นที่ติดตั้งในเครื่อง ถ้าไม่พอ build จะไม่ผ่าน
- `go1.25.3`: บังคับใช้รุ่นนี้เสมอ

ใน CI หรือ Docker image ที่ล็อกรุ่น Go ไว้แล้ว มักตั้ง `GOTOOLCHAIN=local` เพื่อไม่ให้ดาวน์โหลดอะไรระหว่าง build และให้ build ล้มชัด ๆ ถ้ารุ่นไม่ตรง

เวลาอัปเกรดรุ่นของทั้งโปรเจกต์ ใช้ `go get go@1.26` ซึ่งแก้บรรทัด go ให้ แล้วรัน `go mod tidy`

## easy
ตัวอย่าง: go.mod ที่เขียนว่า `go 1.24` และเครื่องติดตั้ง Go 1.25

Go 1.25 build ได้ปกติ เพราะ 1.25 ใหม่กว่ารุ่นขั้นต่ำ ไม่มีการดาวน์โหลดอะไร

## hard
ตัวอย่าง: Dockerfile ที่ใช้ image `golang:1.25` และตั้ง `GOTOOLCHAIN=local` แล้วมีคนแก้ go.mod เป็น `go 1.26`

build ใน Docker จะล้มด้วยข้อความว่าต้องใช้ go 1.26 แต่ใช้ได้แค่ 1.25 ซึ่งเป็นผลที่ต้องการ ทีมจะรู้ทันทีว่าต้องอัปเกรด image ก่อน แทนที่ build จะไปดาวน์โหลด toolchain เองแบบเงียบ ๆ
